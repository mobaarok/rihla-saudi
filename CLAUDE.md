# Rihla Saudi: project guide for Claude

A bilingual (English + Arabic) travel guide website for Saudi Arabia, inspired by the idea of unseenbangladesh.com but with **our own** design, text and photos (never copy theirs). Owner: mobaarok. Repo: `mobaarok/rihla-saudi`.

- Live site (GitHub Pages): https://mobaarok.github.io/rihla-saudi/
- Firebase project: `rihla-saudi` (Auth: Google + Email/Password; Firestore; rules in `firestore.rules`)
- "Rihla Saudi" is still a working name (change it in `src/config/site.ts`). The site is English-first (`defaultLocale` in `src/i18n/routing.ts`).

## Working with the owner

- The owner works in Claude Code on the web (claude.ai/code). Each session starts by selecting the `mobaarok/rihla-saudi` repo (branch `main`). The cloud container is temporary: everything must be committed and pushed to GitHub to be kept.

- End of a feature: update the **Progress** section of this file (and README if user-facing) so the next session knows what changed.

## Owner's rules (always follow)

- **Do not use the owner's Claude API key or credit** to build or test anything. It is reserved for the AI trip planner (phase 4).
- Write user-facing explanations in plain, simple English; the owner is not a native speaker.
- Every user-facing string exists in **both** `src/messages/en.json` and `src/messages/ar.json`, and all content uses `{ en, ar }` (`Localized`). Never ship English-only text.
- Facts must be careful and conservative. Don't invent prices, opening hours or claims you are not sure of; prefer "check before you go". Coordinates and distances are approximate.
- Photos: only freely licensed (Wikimedia Commons CC0/PD/CC BY/CC BY-SA) or the owner's own, always credited. **Check every new photo by eye.** No photo is better than a wrong one.
- Commit or push only when the owner asks; never push untested, broken builds.

## Tech stack

Next.js 15 (App Router) + TypeScript + Tailwind CSS 4 + next-intl 4 (`/en`, `/ar`, RTL for Arabic) + Firebase JS SDK 12 + Leaflet/react-leaflet (map pins) + an SVG region map for the passport. Fonts: Inter, Fraunces, IBM Plex Sans Arabic (`next/font/google`).

## Branches (important)

| Branch | Purpose |
|---|---|
| `main` | Development. A normal Next.js app with `src/middleware.ts` (language redirect). Work here. |
| `gh-pages` | What is published. Same app plus GitHub Pages-only changes: `output: 'export'`, `trailingSlash`, `basePath` from `NEXT_PUBLIC_BASE_PATH`, no middleware, root `src/app/page.tsx` language redirect, root `not-found.tsx`, `public/.nojekyll`, force-static sitemap/robots, `.github/workflows/deploy.yml` (deploys on push to `gh-pages`). |
| `version-1` | Frozen backup of version 1. Don't change it. |

Publishing: `git checkout gh-pages && git merge main && git push` (then `git checkout main`). The merge is clean because the old "revert pages setup" commit on main is already recorded as merged into gh-pages. Keep Pages-only changes on `gh-pages` only. Code must work in both modes: use `assetPath()` (`src/lib/assets.ts`) for files in `/public`, and next-intl `Link`/`useRouter` from `@/i18n/navigation` for internal links (never raw `<a href="/...">`).

## Conventions

- Pages are server components that call `setRequestLocale(locale)` and have `generateStaticParams`/`generateMetadata` (with `alternates` for en/ar). Interactive parts go in small `'use client'` components.
- Pattern for filterable lists: render cards on the server, pass them as `ReactNode` to a client filter (see `FilteredPlaces`, `SearchView`, `SavedList`). Keeps pages indexable.
- Translate with `t(localized, locale)` from `@/lib/content` and `useTranslations`/`getTranslations` for UI strings. Use ICU plurals with Arabic forms (`zero/one/two/few/many/other`).
- Use logical Tailwind classes (`ms-`, `me-`, `ps-`, `start-`, `end-`, `text-start`) so RTL works. Wrap codes and numbers in `dir="ltr"` when needed.
- Design tokens are in `src/app/globals.css` (`sand-*`, `palm-*`, `dune-*`, `ink`, `muted`; `font-display`). Cards: `rounded-2xl border border-sand-200 bg-white`. Buttons: `rounded-full`.
- Adding a place: copy an entry in `src/data/places/<area>.ts`, unique `slug`, all fields in en + ar, `photoQuery` (searches separated by `|`). It gets a page, sitemap entry, map pin and search automatically.
- User data (Firestore `users/{uid}`): `saved[]`, `visitedPlaces[]`, `visitedRegions[]`, `quizScores{region: best}`, `displayName`, `email`, `updatedAt`. Signed-out users use localStorage (`rihla:lists`), merged into the account on sign-in. **If you add a field, update `firestore.rules` and tell the owner to re-publish the rules.**

## Environment notes (cloud sessions)

- The sandbox cannot reach Wikimedia, map tiles or github.io. Photos are fetched by the GitHub Actions photo workflow; pull its commit afterwards (`git pull origin main`).
- GitHub API calls for Pages settings and environments are blocked; the owner changes those in GitHub settings.
- Don't use `pkill -f "next ..."` in a command that contains the same text (it kills its own shell). Kill by PID instead.
